## 6. 已知限制与后续改进

1. **P99 解析为 0**  
   当前 wrk 命令未加 **`-L`**，解析器未读到分位延迟，`p99_ms` 在 JSON 中为 0。容量判定实际等价于 **「目标 RPS 可达 + 无 HTTP 错误」**，**未严格按 P99≤500ms 截断**。  
   **建议**：在 `wrk2_backend.py` 增加 `-L` 并重跑容量，或在论文中明确容量定义。

2. **无 workload.lua**  
   对根路径 `http://127.0.0.1:5000/` 做 plain 压测，**不等同** DSB 官方业务脚本；读多写少/突发需在矩阵阶段挂 lua 或换 URL。

3. **容量上限未探顶**  
   800 RPS 仍 `ok`，真实「 knee 」可能更高；高负载结论需谨慎表述。

4. **单应用**  
   SocialNetwork 需 **换栈 + 单独容量 + 9 格**。
